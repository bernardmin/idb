# HD현대중공업 데이터센터 냉각 최적화 · PUE 개선 — 발표용 데모

제안서(『서버 부하·온도·냉각설정값 기반의 단계형 냉각 최적화 PoC』)의 화면과 숫자를
로컬에서 실제로 동작하는 형태로 재현한 데모입니다.

> **개념 예시 · 실제 데이터 아님.** 실증 시스템이 아니라 발표·설득용입니다.
> 화면 곳곳에 이 표기가 들어가 있습니다.

---

## 1. 실행 방법

### 가장 빠른 방법 — 설치 없이 바로 보기

```
static\index.html  ← 더블클릭
```

`static/` 폴더 안에 화면·데이터·차트 라이브러리가 모두 들어 있습니다.
**Python도, 인터넷 연결도, 서버도 필요 없습니다.** 사내망에서도 그대로 열립니다.

### 데이터부터 다시 만들고 싶을 때

```
run.bat  ← 더블클릭
```

Python 3.11 이상이 필요합니다. 처음 실행하면 데이터 생성 → 진단 → 전처리 →
학습 → 화면 데이터 생성까지 자동으로 돌고(5~10분), 끝나면 브라우저가 열립니다.
두 번째부터는 바로 열립니다.

> Python 설치 시 **"Add Python to PATH"** 를 반드시 체크하십시오.

macOS·Linux는 `./run.sh` 를 쓰십시오.

## 2. 화면 구성 (5개 탭)

| 탭 | 내용 | 제안서 |
|---|---|---|
| 1 데이터 진단 | 결측·고정값·정비구간을 찾아 제외, 비교 가능 시간 비율 | 13p 통과 기준 |
| 2 운전 분석 | 부하는 변하는데 설정은 고정인 구간, 반응 시간 측정 | 4p |
| 3 모델 성능 | 예측 정확도, 지평별 오차, 오차범위 산출 근거 | 11p·13p |
| 4 시뮬레이션 | 3×3 조합 9개, 안전 필터, 과거 사례 검산 | 7p·8p |
| 5 운영 대시보드 | 현재값·변경안·예상 결과·승인 버튼, PUE | 10p |

기본으로 **5번 운영 대시보드**가 열립니다. 발표는 여기서 시작해 근거를 물으면
4 → 3 → 2 → 1 순으로 거슬러 올라가는 흐름을 권합니다.

## 3. 제안서 숫자 재현 결과

데모가 제안서의 숫자를 그대로 만들어내는지 확인한 결과입니다.

| 제안서 | 값 | 데모 | |
|---|---|---|---|
| 2p·10p 현재 상태 | 180kW · 23.8℃ · 22.0℃ · 팬85% | 동일 | ✅ |
| 10p 구역② 부하 | 165kW | 165kW | ✅ |
| 7p 변경안① | 22.5℃ · 팬80% | 동일 | ✅ |
| 7p 예상 온도 | **24.4 ± 0.4℃** | **24.4 ± 0.4℃** | ✅ |
| 7p 변경안② | 23.0℃ · 팬75% → 상한 초과 | 초과로 제외 (9개 중 1개) | ✅ |
| 8p 설정 효과 | 설정 +0.5℃ → 온도 **+0.6℃** | +0.6℃ | ✅ |
| 8p 계산 | 23.8 + 0.6 = **24.4℃** | 24.4℃ | ✅ |
| 8p 오차범위 | ±0.4℃ | ±0.4℃ | ✅ |
| 7p 반응 시간 | 15~30분 | **23분** (데이터에서 측정) | ✅ |
| 13p 데이터 상태 | 90% 이상 | 93.1% | ✅ |
| 13p 예측 정확도 | ±1℃ 이내 80% 이상 | 100% (30분) · 93% (120분) | ✅ |
| 13p 온도 안전성 | 초과 0건 | 0건 | ✅ |
| 8p 과거 사례 시간 | 약 340시간 | **약 101시간** | ⚠️ |

⚠️ **과거 사례 시간만 다릅니다.** 제안서는 "175~185kW 구간 약 340시간"이라고
썼는데, 그러려면 60일 중 24%가 10kW 폭 안에 들어와야 합니다. 이 데모의 부하는
110~230kW로 움직이므로 같은 구간이 101시간 나옵니다. 계산 논리(+0.6℃ → 24.4℃)는
동일하므로 발표에 지장은 없지만, **제안서 수치를 101시간으로 맞추거나 데모 표기를
그대로 쓰는 것 중 하나를 선택**하셔야 합니다.

인수인계서대로 만들면 제안서 숫자가 나오지 않는 부분이 있어 수정했습니다.

| # | 인수인계서 | 문제 | 수정 |
|---|---|---|---|
| 1 | 온도 오프셋 1.2 / 팬 계수 0.035 | 23.8℃ 대신 24.15℃, 24.4℃ 대신 24.83℃ | 설정 이득 1.2배 + 팬 무릎 구조로 교체 |
| 2 | 팬 효과 선형 | 9개 조합 중 초과가 하나도 안 생김 | 팬 78% 아래 비선형(기류 단락) 반영 |
| 3 | PUE 없음 | 고객 요구사항 ②의 절반이 빠짐 | 컬럼·KPI·추이 차트 추가 |
| 4 | 구역 대표온도 단일값 | 제안서 7p "가장 더운 지점" 과 충돌 | 랙 4개 생성 → 최댓값을 대표온도로 |
| 5 | 대시보드 "-1.4kW" | 제안서는 "감소 방향"만 표기 (원칙 위반) | "감소 방향" + 계산 근거를 작게 |

| 7 | 타깃 = 30분 후 온도 | 현재 온도 복사만으로 좋은 점수가 나옴 | 변화량(Δ) 타깃 + "현재값 유지" 기준선 병기 |

## 5. 모델 구조 — 왜 이렇게 만들었는지

**AI가 하는 일은 두 군데뿐입니다.** [2] 학습과 [8] 재학습. 안전 판정과 후보 제외는
규칙이라 "왜 빠졌는지" 항상 설명할 수 있습니다. (제안서 11p)

예측은 두 조각으로 나눠 각각 데이터가 많은 곳에서 학습합니다.

```
예측(h분 후) = 기준 예측(h)              ← 아무것도 안 바꿨을 때 (직접 회귀)
             + 응답비율(h) × 평형 변화량   ← 설정을 바꿔서 생기는 추가분
```

- **기준 예측** — 30/60/90/120분을 각각 직접 예측합니다. 예측을 예측에 물리지
  않으므로 오차가 누적되지 않습니다.
- **평형 변화량** — 설정온도 효과는 과거 설정 변경 73건의 평균 계단응답에서
  측정(1.21℃/℃), 팬 효과는 안정 구간 6.3만 행 회귀에서 학습.
- **응답 비율** — 같은 계단응답 곡선에서 시상수 23분을 읽어 `1-exp(-h/23)`.

> 30분 후 온도를 한 번에 회귀하는 방식(인수인계서 원안)도 만들어 봤지만,
> 설정 변경 직후 행이 9만 행 중 270행뿐이라 설정 반응의 1/6밖에 배우지
> 못했습니다(실측 +0.42℃ / 학습 +0.07℃). 위 구조로 바꿔 해결했습니다.
> 자세한 근거는 `src/equilibrium.py` 주석에 적어 두었습니다.

**오차범위**는 부하 구간 × 팬 구간별 잔차 표준편차로 산출하고, 표본이 적은
조합은 넓혀서 보수적으로 판정합니다. 그래서 팬 75%(표본 적음) 조합의 밴드가
넓어지고, 23.0℃·팬75%가 상한 초과로 걸러집니다.

## 6. 폴더 구조

```
hd-cooling-demo/
├── run.bat / run.sh            실행
├── requirements.txt
├── src/
│   ├── config.py               모든 계수·기준값 (숫자가 안 맞으면 여기부터)
│   ├── generate_data.py        90일 1분 단위 가상 데이터
│   ├── diagnose.py             [1] 데이터 진단
│   ├── preprocess.py           결함 제외 + lag feature
│   ├── train.py                [2][3] 학습·검증
│   ├── equilibrium.py          평형온도 + 응답속도 (시뮬레이션용 모델)
│   ├── simulate.py             [4][5][6] 시뮬레이션·안전필터·정렬
│   └── export_web.py           화면용 data.js 생성
├── static/
│   ├── index.html              화면 5개 탭 (단일 파일)
│   ├── data.js                 미리 계산된 결과
│   └── vendor/chart.umd.js     차트 라이브러리 (오프라인)
├── data/ models/ reports/      생성물 (git에 올리지 않음)
```

`data/`(140MB)와 `models/`(54MB)는 저장소에 올리지 않습니다. `run.bat`이
다시 만듭니다. 화면에 필요한 것은 `static/`(740KB) 안에 모두 있습니다.

## 7. 이번 범위가 아닌 것

- **자동 제어를 하지 않습니다.** 운영자 승인 버튼까지입니다. 버튼을 눌러도
  설비에 아무 명령도 가지 않습니다.
- **절감률을 확정 수치로 제시하지 않습니다.** "감소 방향"과 계산 근거만 표시합니다.
- 실제 계측 데이터가 아닙니다. 전력 계량 범위·허용온도·랙 온도센서 유무는
  현장 확인 후 확정해야 합니다.
